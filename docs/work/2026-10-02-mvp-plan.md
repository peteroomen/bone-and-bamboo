# MVP plan

**Goal:** a complete, offline, phone-first mahjong-tile roguelike: four rounds against friendly
hosts, the wall, the teahouse, curios and fortunes, a sparrow who teaches, a collection, sound,
and saves. The rules and numbers are in `docs/design.md`.

**Who does what:** a builder session implements the milestones below, in order. The planner (a
separate session) reviews each milestone, validates it by running the checks and playing, and
works on the generated art with the user. The user merges.

## How to work

- One branch, `mvp`, and one draft PR into `main` titled "MVP". Push after every milestone (and
  more often if you like).
- Keep the PR description as a checklist of the milestones below; tick each one when its
  acceptance checks pass, and add one line under it saying what you verified.
- Before ticking a milestone: `pnpm lint`, `pnpm typecheck`, `pnpm test` all clean; for UI
  milestones also `pnpm build` and `pnpm e2e`, and look at the screenshots.
- Don't change rules or numbers in `docs/design.md`. If something doesn't work as written, add a
  note under "Questions for the planner" in the PR description, pick the smallest sensible
  workaround, and carry on.
- Keep `CLAUDE.md`'s "Current state" up to date at each milestone.
- Conventional commits. No model names in commits or code.

## Reuse from Twelve Petals

`peteroomen/hanafuda-roguelike` is the sibling game with the same stack. Attach it read-only
(the `add_repo` tool) and copy what fits rather than rewriting it. Adapt names and remove what is
koi-koi specific. Worth taking:

- Tooling: `package.json` scripts and dev dependencies, `tsconfig.*.json` (engine, sim, app, node),
  `eslint.config.js` (the engine purity rules), `vite.config.ts` (PWA), `playwright.config.ts`
  (phone, small phone and desktop projects), `vercel.json`, husky and lint-staged.
- Engine: `src/engine/rng.ts` (seeded, serialisable), the reducer pattern returning
  `{ state, events }`, `testkit.ts`.
- UI infrastructure: `src/ui/game/Viewport.tsx` and `stageSize.ts` (stage scaling, desktop
  framing), `src/ui/keys.ts` and `input.ts`, `src/ui/state/store.ts` (saves and migrations),
  `pwa.ts`, `transfer.ts`, `src/ui/screens/OfflineSettings.tsx`, the page-turn transition
  (`PageTurn.tsx`, `pageTurn.ts`), sheets and `useSheetKeys`, the tip queue in `useGame.ts`.
- Audio: `src/ui/audio/core.ts`, `physical.ts`, `instruments.ts`, `compose.ts`, `music.ts`
  (rewrite the scapes and calls for this game), `haptics.ts`.
- `global.css` type scale (`--fs-*`) and the woodblock flat-fill conventions, re-coloured.

## Milestones

### M1 · Scaffold

Vite + React 19 + strict TypeScript (`noUncheckedIndexedAccess`), the `@/*` alias, the engine
purity rules (no DOM, React, `Math.random`, `Date` under `src/engine`, `src/content`, `src/sim`),
Vitest, Playwright at 390×844, 360×640 and desktop 1366×768, vite-plugin-pwa, `vercel.json`.
`src/` laid out as `engine/`, `content/`, `sim/`, `ui/`. An app shell that shows a title.

**Accept:** lint, typecheck, test, build and e2e all pass on the empty shell; the e2e screenshot
shows the title at all three sizes.

### M2 · Engine and simulator

- `content/`: tiles, sets (prices and levels), curios, fortunes, enhancements, packs, targets,
  money, lanterns, tile sets, hosts. Every number from `docs/design.md` lives here.
- `engine/`: tile set building, the wall (deal, visibility, take), the round reducer (fill, play,
  discard, refill, end, score with per-step events), the run reducer (rounds, targets, money,
  gift, shop, packs, fortunes, burn a kind, sell, reroll), set detection and validation.
- `engine/ai.ts`: the hint bot (play / discard / which stack), ported from
  `tools/sim-py/runsim.py` (`RunRound`), and the smart and casual shoppers.
- `sim/`: `pnpm sim` plays rounds and runs headless (`--runs`, `--shopper smart|casual`,
  `--targets`, `--seed`), printing the tables in `docs/balance/`.

**Accept:** unit tests cover set detection (every set type, honours never in runs), scoring
(the worked example below), the wall's visibility rules, each curio, fortune and pack, the money
rules, and save round-trips (state is plain JSON). `pnpm sim` reproduces the Python results within
noise: base round median 2,450 ± 10% (greedy, see 1 under, 3 discards, cheap prices), and on the
recommended ladder the smart shopper wins 71% ± 6 and casual 24% ± 6 over 400 runs.

Worked scoring example: table = chow 2-3-4 Bamboo, pong of 9 Characters, chow 6-7-8 Dots, no
levels, no curios: chips (10+9) + (40+27) + (10+21) = 117, mult 1 + 4 + 1 = 6, score 702.

### M3 · A round on screen (grey box)

The table at phone size: the wall's 8 stacks (fanned so the strip of the tile under each top
shows), your hand of 8, your table of played sets, the plays and discards left, the target and the
live score preview. Tap tiles to select; Play and Discard buttons that enable only when legal;
tap a stack to take its top tile; Auto refill. Tiles drawn by `src/ui/art/tiles.ts` (ported from
`art-source/tiles/tiles.js`, with the three colourways). The scoring count-up at round end.
Animations driven by engine events (tile flies from stack to hand, set to table).

**Accept:** an e2e plays a whole round through the UI at all three sizes and screenshots the start,
mid-round and the score count. Everything important is visible at 360×640 without scrolling;
touch targets are at least 44px (a stack is a target, not each tile in it).

### M4 · The run

Rounds 1-4 with the targets, the round-won and run-over screens, money, the gift scene (1 of 2
rare curios), the teahouse (curios, almanac, fortunes, packs, reroll, burn a kind, sell), the curio
row and fortune pocket (a player bar docked at the foot of every run screen, as in Twelve Petals),
the set picker, enhancements on tiles. Save and resume at any point.

**Accept:** an e2e plays a full four-round run through the UI with scripted choices; reloading the
page mid-round and mid-shop resumes exactly. `pnpm sim` still matches M2.

### M5 · Hosts and twists

The host choice before each round, the eight hosts and their twists as data, the beast's harder
target and bigger gift. Portraits are placeholders until the art lands. Add the twists to the
simulator and print a per-host table (win rate of the round, median score against target).

**Accept:** each twist has a unit test and shows in the UI (a banner with the rule); the per-host
sim table is in `docs/balance/`, with any host whose round win rate is more than 15 points off the
folk spirit's flagged under "Questions for the planner".

### M6 · The sparrow

The guided first run (fixed seed, tip queue), the three hint levels, Ask the sparrow, the set book.

**Accept:** e2e: a new profile gets the guided run; tips queue and block play until dismissed;
Ask the sparrow returns a legal move in every state the e2e reaches.

### M7 · Around the game

Title (Continue, New run, Collection, Settings), new-run setup (tile set and lantern), the
collection, settings (including colourway until the style is chosen), unlocks for the two extra
tile sets and the lanterns, offline install and save transfer.

**Accept:** e2e: win a run (scripted seed) and see the unlock; settings persist; the offline panel
and the save code round-trip work.

### M8 · Sound, haptics and feel

Tile clacks (take, place, play, discard), the opera percussion for plays and the score count,
music per wind with a calm shop scene, haptics, speed settings (instant skips animations).

**Accept:** an e2e measures that audio plays and stops when the tab is hidden; instant speed
plays a round with no animation waits.

### M9 · Art and polish

Integrate the generated art as the planner delivers it (cut-out hosts and sparrow, backdrops,
traced object sheets for curios, fortunes and packs), the desktop layout check, a full balance
pass with `pnpm sim`, and deploy to Vercel.

**Accept:** the full-run e2e at all three sizes with real art; the planner signs off.

## Placeholders until the art lands

- Hosts and the sparrow: a circle in the host's colour with its name's first letter, at the size
  the portrait will have. Keep the crop data shape (`close`, `full`) ready for real art.
- Curios, fortunes, packs: a rounded square with a simple glyph per kind. The traced art will
  arrive as a generated TypeScript file of paths, as `charmArt.ts` does in Twelve Petals.
- Backdrops: a flat seasonal colour.

## Out of scope for the MVP

Editions and chops (art exists), flowers and seasons as bonus tiles, endless mode, daily seed,
more hosts, a map, app stores, localisation.
